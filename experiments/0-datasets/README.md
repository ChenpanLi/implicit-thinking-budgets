# 0 · Datasets

Builds the eight item pools that every later stage reads. Each pool is a JSONL file
with one atomic item per line. Every item has a stable id (`q-0000`, or `atom-0000` for
integrals), and every batch and run refers to items by that id.

| Dataset | Source | Items |
| --- | --- | --- |
| integrals | generated by us, shipped in `datasets/integrals/` | 1000 |
| onewordqa | generated by us, shipped in `datasets/onewordqa/` | 1548 |
| gpqa-diamond | `Idavidrein/gpqa` (`gpqa_main` restricted to `gpqa_diamond`) | 196 |
| gsm8k | `openai/gsm8k`, test split | 1319 |
| math500 | `HuggingFaceH4/MATH-500` | 500 |
| mmlu | `edinburgh-dawg/mmlu-redux-2.0`, 19 subjects × 74 | 1406 |
| strategyqa | `ChilleD/StrategyQA`, test split | 687 |
| aime | `HuggingFaceH4/aime_2024` + `yentinglin/aime_2025` | 60 |

The Hub datasets are read at the revisions pinned in `src/llm/pools/<dataset>.py`, so a
rebuild produces the same bytes as the pools the paper used. GPQA is gated: accept its
terms on the Hub and set `HF_TOKEN` before building it. GPQA-Diamond keeps the ids and
option order of the full GPQA-main pool, which is why its ids are not contiguous; 2 of
the 198 diamond questions are dropped because their answer options are not distinct.

## Run

```bash
bash experiments/0-datasets/build.sh          # all eight
bash experiments/0-datasets/build.sh gsm8k    # one
```

Each job is `python -m llm.pools <dataset>`. CPU only; it takes a few minutes, mostly
spent downloading.

## Output

```
$RUN_DIR/datasets/<dataset>.jsonl
$RUN_DIR/datasets/<dataset>.manifest.json    source, pinned revision, counts, rejects
```

A pool already on disk is left untouched if it is identical to the rebuild. If it
differs, the build stops instead of overwriting it. Pass `--force` to
`python -m llm.pools` only if you mean to replace it.
